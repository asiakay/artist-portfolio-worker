What the front end delivers

Built for serverless deployment on Cloudflare Workers, this interface balances warmth with clarity so communities can focus on accountability, not tooling.

Submission workspace

Responsive form patterns for deeds, supporting attachments, location context, and partner tagging.

Verification dashboard

Role-based review queues with filters, inline status updates, and audit history for every action.

Public ledger

SEO-friendly, searchable listing so supporters can browse impact by neighborhood, theme, or partner.

Workflow at a glance

Each stage is modular, allowing integrations with KV, D1, Supabase, or other Cloudflare services.

  1. 1

    Submit a deed

    Residents log an action with supporting media. Form validation runs at the edge to keep inputs clean.

  2. 2

    Partner review

    Stewards receive notifications, leave notes, and confirm details before the deed is published.

  3. 3

    Public ledger

    Verified deeds appear instantly for the community with filters and open data exports.

Frequently asked questions

Use these copy blocks as a starting point for your deployment documentation.

Can this deploy directly to our Cloudflare network?

Yes. Place this folder in your `public/` assets directory. The Worker automatically serves `/deeds/` via the asset binding configured in wrangler.toml.

Where do deed submissions go?

Connect the front-end form to a Worker route or Durable Object. You can stream payloads to KV, D1, or external APIs without leaving Cloudflare’s edge.

How do we style it for our collective?

Update the color CSS variables in assets/deeds.css and replace copy in the HTML. Components are built with modern, semantic HTML so theming is straightforward.

Ready to log your first deed?

Hook this interface up to your Cloudflare Worker endpoint to start receiving community submissions within minutes.
